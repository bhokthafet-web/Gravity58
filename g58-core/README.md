# G58 Core

G58 Core is the first-party backend for Gravity58: a G58-owned API, PostgreSQL database, authentication service, local media storage, realtime event stream and administration console.

## Production status

This stack owns `server.g58.in` in production. Caddy terminates HTTPS and forwards requests to the private API container. PostgreSQL and uploaded media are stored in private Docker volumes. The public GitHub Pages site calls this service through `https://server.g58.in/api/v1`.

## Local start

1. Copy `.env.example` to `.env`.
2. Generate independent strong values for `POSTGRES_PASSWORD` and `BOOTSTRAP_ADMIN_PASSWORD`.
3. Configure the existing Brevo SMTP relay values for password-reset delivery.
4. Run `docker compose up -d --build`.
5. Open `http://localhost:8088/console/`.

## Production endpoints

- `https://server.g58.in/api/v1` — customer and application API
- `https://server.g58.in/console/` — private G58 administrator console
- PostgreSQL and media volumes are private and must never be exposed publicly.

## Security decisions

- Passwords use Argon2id.
- Browser sessions use random opaque tokens; only SHA-256 token hashes are stored.
- Cookies are Secure, HttpOnly and SameSite=Lax.
- Public and private record visibility is decided by the server, never by browser-supplied permissions.
- All privileged changes are written to the audit log.
- Password reset tokens are single-use and expire after 30 minutes.
- Media paths are generated by the server; user filenames are never used as filesystem paths.

## Operations

- `ops/stage-on-hostycare.sh` builds and validates the API and database.
- `ops/cutover-hostycare.sh` starts the G58 HTTPS proxy and verifies the public health endpoint.
- Run `npm test` inside this folder for security and access-control tests.
- Back up the PostgreSQL and media volumes off-server on a daily schedule and test restores regularly.
