# G58 Core

G58 Core is the first-party backend for Gravity58. It replaces Appwrite with a G58-owned API, PostgreSQL database, authentication service, local media storage, realtime event stream and administration console.

## Isolation rule

This stack is deployed beside the current Appwrite service until the compatibility adapter and every secure action pass the existing unit and browser tests. Do not point the production website at G58 Core early.

## Local start

1. Copy `.env.example` to `.env`.
2. Generate independent strong values for `POSTGRES_PASSWORD` and `BOOTSTRAP_ADMIN_PASSWORD`.
3. Configure the existing Brevo SMTP relay values for password-reset delivery.
4. Run `docker compose up -d --build`.
5. Open `http://localhost:8088/console/`.

## Production endpoints

- `https://api.g58.in/api/v1` — customer and application API
- `https://console.g58.in` — private G58 administrator console
- PostgreSQL and media volumes are private and must never be exposed publicly.

## Security decisions

- Passwords use Argon2id.
- Browser sessions use random opaque tokens; only SHA-256 token hashes are stored.
- Cookies are Secure, HttpOnly and SameSite=Lax.
- Public and private record visibility is decided by the server, never by browser-supplied permissions.
- All privileged changes are written to the audit log.
- Password reset tokens are single-use and expire after 30 minutes.
- Media paths are generated by the server; user filenames are never used as filesystem paths.

## Remaining migration gates

- Port all secure Digital Menu and Refills actions from the Appwrite function.
- Add the browser compatibility adapter and remove Appwrite SDK scripts.
- Add PostgreSQL-backed multi-instance realtime notifications.
- Add encrypted daily off-server backups and a tested restore procedure.
- Run the complete G58 unit, browser and Android smoke-test suites.
- Switch DNS/API configuration only after a signed migration report.
